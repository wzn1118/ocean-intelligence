## 根因收敛与最小方案

### 已定位到的行为

以下源码分析对应本轮读取时的内容；主线程并行后续修改不属于本报告的修改，也不作为本批既有 PDF 的生成证据。

1. 同一探针、同一字体属性、不同 PDF 后端产生不同的实际字体与字符结果。**FontName 属性与安装可用性只证明请求，不证明输出字体。** 五字体在两旧版都不出现在 listfonts 中，却均由 helper 确认为可用；其中 WenQuanYi 原生成功、Noto 原生失败，不能把 listfonts 不包含字体当作充分根因。
2. 两旧版对五字体一律走 print 都得到 Courier 未嵌入，所以**仅把主题改成 WenQuanYi，但继续走 print，不会解决本批旧版嵌入问题**。
3. [主题选择](/opt/ocean-intelligence/codex-runtime/matlab/assets/oi_ocean_theme.m:37) 当前优先 Noto；[导出字体选择](/opt/ocean-intelligence/codex-runtime/matlab/assets/oi_export_figure.m:508) 又优先复用 `OI_OceanTheme.FontName`。仅重排导出器备用候选，不会覆盖一个仍被认定可用的缓存 Noto 主题。
4. [主导出版本分支](/opt/ocean-intelligence/codex-runtime/matlab/assets/oi_export_figure.m:95) 为保证精确页面，在 R2025a 之前预选 print；这与已得到字体证据的旧版 WenQuanYi 原生路径不同。

本报告未检查字体二进制结构、字体授权位或 MATLAB 内部字体解析器，因此不把 Noto 的失败武断归因为 CFF、TTC、授权或某个内部库缺陷。

### 可立即实施的最小字体修复

对这批环境的 CJK+Latin 混合输出，先将 **WenQuanYi Zen Hei 作为显式出版字体**；在创建图窗/主题时选择，并同步导出器所读取的 `OI_OceanTheme.FontName`。不要伪造 Noto 的“未安装”状态，也不要修改字体可用性 helper 来承载导出兼容策略。

以下是针对已有 `figureHandle`、新文件路径 `outputPdf` 的最小原生导出调用，供主线程执行；本轮没有执行或改源码：

```matlab
fontName = "WenQuanYi Zen Hei";
assert(oi_font_available(fontName));
assert(~isfile(outputPdf));
set(findall(figureHandle, "-property", "FontName"), "FontName", fontName);
drawnow;
exportgraphics(figureHandle, outputPdf, ...
    "ContentType", "vector", "BackgroundColor", "white");
```

上述调用对应本批已实跑的字体/后端组合，**输出是内容裁剪 PDF**。主线程若随后调用会重新应用主题的 `oi_export_figure`，必须同时更新主题，否则可被改回 Noto。

MathWorks 官方说明 vector PDF 包括可嵌入字体，不承诺每个请求字体都一定正确输出；本报告以实际 pdffonts、精确文本比对和渲染补足该证据。[官方 exportgraphics 文档](https://ww2.mathworks.cn/help/matlab/ref/exportgraphics.html)

### 与精确尺寸合同的衔接

- R2025a+：保留原生 `Units="inches"`、`Width=widthPixels/dpi`、`Height=heightPixels/dpi`、`Padding="figure"`、`PreserveAspectRatio="on"`，PNG 另传输出 Resolution。先应用 WenQuanYi，再按最终物理尺寸完成布局和 drawnow，重新导出原 publication。该精确尺寸组合不在本字体探针中，仍须真实验证。
- R2021a/R2024b：这批证据支持 WenQuanYi 的原生内容裁剪 PDF，不支持“旧版原生精确页面已解决”。**在不改变当前精确页合同的前提下，本轮没有已实证的完整旧版出版修复。** 不擅自放松评分/尺寸断言，不手改 PDF 页面盒，不改 PNG 像素冒充 native，不将已知失败的 print 字体输出标为成功。若另有显式允许内容裁剪 PDF 的交付模式，应记录实际页尺寸和 `export_api="exportgraphics"`，不得冒充精确页面模式。
- 不将 Droid 作为全图统一字体：旧版 Latin 已确认不可用。也不将 DejaVu/Liberation 作为跨版本 CJK 解决方案：旧版标题失败，新版实际依赖 WenQuanYi 回退。

Width/Height/Padding/Units/PreserveAspectRatio 在本地 MATLAB 自 R2025a 起提供；默认导出为内容紧裁剪。[官方尺寸参数与版本说明](https://ww2.mathworks.cn/help/matlab/ref/exportgraphics.html)

### 下一次必须验收的内容

1. 使用原 publication 的真实 4×2.25 英寸、300 DPI、粗体标题、中文横纵轴和图例，分别实跑三版本；不能只复用本探针 normal 字重的结论。
2. PDF 分别核对真实 API、页数、MediaBox/CropBox、所有字体的 emb 状态；精确页面模式仍应得到 288×162 pt。
3. 文本逐字匹配预期六字标题和实际中文轴标签；同时精确匹配 `Observed 20.125`、`Model 21.50`。不要用“存在任意汉字”或 `uni=yes` 替代正确文本。
4. 整页渲染逐份检查标题、旋转纵轴、图例文字/边框、横轴标签间距。必须将嵌入、可检索性、实际字形和布局分开报告。
5. 继续保持未验证的跨格式、粗体、更多 CJK 字形、SVG/PNG 视觉及整体评分状态不变，直到对应产物确实检查过。
